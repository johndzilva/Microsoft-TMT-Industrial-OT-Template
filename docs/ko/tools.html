명령줄 도구#

source 폴더에는 TMT 밖에서 모델을 만들고 점검하는 Python 3 도구가 있습니다. 선택 사항이며, 이 사이트의 나머지 내용은 TMT만으로 할 수 있습니다.

도구 기능
build_model.py JSON 아키텍처 설명으로 .tm7을 만듭니다. 자동 배치, 앵커 흐름 설정, 미리보기 그림, 예상 위협 목록을 함께 제공합니다
check_model.py .tm7을 점검합니다: 위협이 반복되거나 빠질 구성요소, 읽기 전용 저장소, 병렬 흐름
predict.py TMT가 생성할 위협을 흐름별로 예측합니다
render_dfd.py 모델 다이어그램의 미리보기 그림을 그립니다
tb7_to_kb.py File > Apply Template처럼 템플릿을 모델에 넣습니다
release_check.py 릴리스 전 템플릿과 예제를 자동 점검합니다

필요 조건: Python 3. PNG 미리보기에는 Playwright와 Chromium이 필요합니다. 필요 없으면 미리보기 파일 이름을 .svg로 지정하세요.

아키텍처 설명으로 모델 만들기#

cd source
python build_model.py ../examples/specs/gas_pipeline.json \
  "../OT Plant and Site Risk Assessment Template (IEC 62443).tb7" \
  "../my-site.tm7" --preview my-site.png

설명 파일에는 영역, 요소, 흐름, 선형 경계를 나열합니다.

{
  "name": "Gas Pipeline - Site Risk Assessment",
  "zones": [
    {"id": "cc", "label": "Pipeline Control Centre - Level 2 and 3", "stencil": "SE.TB.B.OT.Zone",
     "props": {"ZonePurdueLevel": "Level 2 - Supervisory", "ZoneSLT": "SL 2"}}
  ],
  "elements": [
    {"id": "scada", "label": "Pipeline SCADA Server", "stencil": "SE.P.OT.SCADA", "zone": "cc",
     "props": {"UserAccounts": "Yes", "PatchStatus": "Patches pending"}},
    {"id": "oem", "label": "Compressor OEM Remote Support", "stencil": "SE.EI.OT.Vendor", "side": "left"}
  ],
  "flows": [
    {"label": "Station telemetry over cellular", "from": "scada", "to": "rtr", "stencil": "SE.DF.OT.DNP3",
     "props": {"ProtocolSecurity": "None", "CarriesControl": "Yes", "Medium": "Cellular"}}
  ],
  "lines": [
    {"label": "Carrier network to remote sites", "stencil": "SE.TB.L.OT.Internet",
     "crosses": ["Station telemetry over cellular"]}
  ]
}
  • 스텐실 ID는 스텐실 페이지에 있습니다. 속성 이름은 ProtocolSecurity, PatchStatus 같은 내부 이름이고, 값은 TMT에 표시되는 값입니다. 알 수 없는 이름이나 값은 거부됩니다.
  • 배치. 영역은 나열한 순서대로 왼쪽에서 오른쪽으로 배치되므로 Purdue 순서로 나열하세요. 영역이 없는 요소는 left, right, bottom에 둡니다. 흐름이 요소를 관통하지 않도록 요소를 정렬하고 흐름을 구부리며, 모든 것을 TMT 그리기 영역 안에 둡니다. 요소에 "pos": [x, y], 흐름에 "bend": [dx, dy]를 지정해 직접 조정할 수 있습니다.
  • 앵커. Threats on this Flow를 자동으로 설정합니다. 각 요소로 들어오는 가장 노출된 흐름에는 All, 나머지에는 Without component threats를 설정합니다. 읽기 전용 저장소에는 Show Data Store Threats for Source Store를 설정합니다. 명세에 직접 지정한 값은 유지됩니다.
  • 결과물. 템플릿이 포함된 .tm7, 흐름별 예상 위협, 미리보기 그림이 만들어집니다. TMT에서 모델을 열고 Analysis View로 전환한 뒤 저장하세요.

모델 점검#

python check_model.py "../my-site.tm7"

모델을 직접 수정한 뒤나 오래된 모델에 2.0 템플릿을 적용한 뒤에 실행하세요. 다음을 알려 줍니다.

  • 둘 이상의 앵커 흐름에 표시되거나, 어디에도 표시되지 않는 구성요소
  • 여러 흐름이 Auto로 남아 있는 구성요소
  • 들어오는 흐름도 원본 저장소 설정도 없는 저장소
  • 채널 위협을 반복할 병렬 흐름

위협 예측#

python predict.py "../OT Product and System Threat Template (IEC 62443).tb7" "../my-model.flows.json"

.flows.json 파일은 build_model.py가 모델 옆에 만듭니다. 예측은 TMT가 생성하는 결과와 일치하며, 두 예제 모두 TMT에서 예측과 같은 개수가 나왔습니다.

Claude와 함께 쓰기#

ot-tmt-threat-model Claude 스킬은 build_model.py를 감싼 것입니다. Claude에게 네트워크 아키텍처나 자산 목록을 주면 데이터 흐름도를 그리고 .tm7을 만들어 줍니다.
