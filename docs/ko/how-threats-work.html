위협이 생성되는 방식#

TMT는 데이터 흐름마다 위협을 생성합니다. 템플릿 2.0은 각 위협이 제자리에서 한 번만 나타나도록 합니다.

문제#

TMT는 모든 흐름에 대해 모든 위협 규칙을 흐름의 출발지, 대상, 흐름 자체와 대조합니다. 따로 처리하지 않으면, PLC의 기본 자격 증명처럼 구성요소에 관한 위협이 그 PLC로 들어오는 흐름마다 한 번씩 나타납니다. 버전 1.3으로 수행한 실제 검토에서는 생성된 위협의 약 절반이 반복이거나 적용 불가로 판정되었습니다.

위협 계열과 앵커#

모든 위협은 하나의 계열(family)에 속하고, 계열마다 하나의 앵커(anchor)가 있습니다. 앵커는 TMT가 그 위협을 생성하는 유일한 흐름 유형입니다.

계열 다루는 내용 생성되는 곳
1 채널 전송 구간의 도청, 스푸핑, 재전송, 주입 네트워크 매체로 영역이나 네트워크 경계를 넘는 흐름
2 기술 대상 스텐실 유형의 약점(웹 UI, HMI, OPC 서버, 안전 제어기) 구성요소의 앵커 흐름
3 구성요소 대상의 수명주기: 자격 증명, 패치, 펌웨어, 디버그 포트, 암호, 로깅 구성요소의 앵커 흐름
4 호스트 호스트의 악성코드, OS 하드닝, 공격 도구 호스트의 앵커 흐름. Runs on a Host Shown in the Model로 표시한 소프트웨어에는 생성되지 않음
5 경로 하나의 공격 경로: 이 출발지가 이 대상에 도달(벤더 접근, 내부자, USB, 클라우드 명령) 경로가 존재하는 모든 흐름
6 제품 수명주기 빌드 파이프라인과 코드 서명 침해 제품당 한 번, Software Supply and Build Pipeline 흐름
7 로컬 경계 격리 우회, 배선 변조 Process or Privilege 또는 Physical Access 경계를 넘는 흐름과 하드와이어 신호
8 저장 데이터 저장된 데이터의 변조, 노출, 손실 저장소로 들어오는 앵커 흐름. 아무도 쓰지 않는 저장소는 나가는 흐름 하나(ID가 R로 끝남)

설정: Threats on this Flow#

이 흐름 속성으로 흐름에 표시할 계열을 고릅니다.

값 채널·로컬 경계 (1, 7) 경로 (5) 구성요소·호스트·저장 데이터 (2, 3, 4, 8) 용도
Auto (기본값) ✓ ✓ 흐름이 신뢰 경계를 넘거나 외부 상호작용자에서 올 때만 직접 그릴 때. 1.x 방식
All ✓ ✓ ✓ 앵커: 각 구성요소로 들어오는 흐름 하나
Without component threats ✓ ✓ – 그 구성요소로 들어오는 나머지 흐름
Component threats only – – ✓ 채널은 다른 곳에 이미 표시된 앵커 흐름
Path threats only – ✓ – 이미 표시된 채널과 병렬인 흐름
None – – – 맥락 설명용으로만 그린 흐름

도구에 맡기세요

build_model.py는 각 요소로 들어오는 흐름 중 가장 노출되고, 네트워크를 쓰고, 제어 명령을 전달하는 흐름에 All을, 나머지에 Without component threats를 설정합니다. check_model.py는 위협이 반복되거나 빠질 구성요소를 알려 줍니다. 명령줄 도구 참조.

그 밖의 규칙#

  • 네트워크가 아닌 매체. Physical Medium = Hardwired signal(4-20 mA 루프, 트립 입력)이나 Local operator input인 흐름은 네트워크 채널이 아닙니다. 도청·스푸핑 위협은 생략되고 배선 변조 위협(OT-T30, PL-T11)이 대신 적용됩니다.
  • 구체적인 위협이 우선. 구체적인 위협이 공격을 다루면 일반 위협은 빠집니다. 무선 링크에서는 무선 도청(OT-I10)이 일반 도청(OT-I01)을 대신합니다. 안전 흐름에서는 안전 프로토콜 변조(OT-T11)가 일반 변조를 대신합니다. 스위치와 방화벽에서는 네트워크 장치 DoS(OT-D08)가 일반 DoS를 대신합니다.
  • 적용될 수 없는 속성은 고정. 소프트웨어 스텐실은 하드웨어 질문을 Not applicable로 고정하므로 하드웨어 위협이 생성되지 않습니다.
  • 범위. 요소의 Assessment Scope = Out of scope는 그 요소의 위협을, 흐름의 Threats on this Flow = None은 그 흐름의 위협을 없앱니다.
  • 읽기만 하는 데이터. TPM 키 저장소처럼 아무도 쓰지 않는 저장소는 나가는 흐름 하나에 Show Data Store Threats for Source Store = Yes를 설정합니다. 저장 데이터 위협이 R로 끝나는 ID로 나타납니다.
