Microsoft TMT 사용법#

Microsoft Threat Modeling Tool에서 모델을 그리고, 속성에 답하고, 위협을 생성해 검토하는 방법입니다.

다이어그램 그리기#

  1. 요소 배치Stencils 창에서 스텐실을 캔버스로 끌어다 놓습니다. Generic Process보다 EDR PLC or Process Controller처럼 가장 구체적인 스텐실을 쓰세요. 스텐실에 따라 적용되는 기술 위협이 정해지고, 스텐실이 이미 아는 속성은 고정됩니다.
  2. 흐름으로 연결프로토콜 스텐실(예: Modbus TCP)을 캔버스에 놓고, 화살표 양 끝을 요소 위로 끌어 붙입니다. 흐름은 한 방향입니다. 명령은 내려가고 상태는 올라오는 경우처럼 양방향이 모두 중요하면 흐름을 두 개 그립니다.
  3. 신뢰 경계 그리기상자형 경계(IEC 62443 Security Zone, Safety Zone SIS, Industrial DMZ, Component or Device Boundary, Enterprise or IT Zone, Vendor or Cloud Boundary)는 끌어다 놓고 영역 안 요소를 감싸도록 크기를 조절합니다. 선형 경계(IEC 62443 Conduit, Internet or Untrusted Network Boundary, Physical Access Boundary, Process or Privilege Boundary)는 가로지르는 흐름 위에 선으로 그립니다.
  4. 모든 것에 이름 붙이기이름은 위협 제목에 그대로 쓰입니다("Spoofing of commands from Engineering Workstation to Line 3 PLC"). 알아보기 쉬운 이름을 쓰세요.
  5. 속성에 답하기요소와 흐름을 하나씩 선택해 Element Properties에서 질문에 답합니다. 속성 참조.
  6. 저장모델을 .tm7 파일로 저장합니다. 템플릿이 모델 안에 함께 저장되므로 다른 PC에서도 템플릿 없이 열 수 있습니다.

그리기 영역 안에 두세요

다이어그램을 약 1800 × 1100 픽셀 안에 그리세요. 이보다 훨씬 바깥에 있는 요소가 있으면 TMT는 파일을 열 때 손상되었다고 표시합니다.

속성에 답하기#

  • 모든 질문은 Unknown에서 시작하며, 이 상태에서는 해당 위협이 모델에 남습니다. 안전하지만 결과가 많아지므로, 없는 기능에는 No로 답하세요.
  • Predefined Static Attributes 아래의 회색 값은 스텐실이 고정한 것입니다. 예를 들어 소프트웨어에는 디버그 포트가 없고, HTTPS는 항상 무결성과 암호화를 제공합니다.
  • (record only) 표시가 있는 질문은 기록용이며 위협에는 영향을 주지 않습니다.

위협 생성과 검토#

  1. Analysis View로 전환View > Analysis View. TMT가 모든 데이터 흐름의 위협을 생성하고, 상태 표시줄에 개수를 보여 줍니다(예: "138 Threats Displayed").
  2. 위협 읽기Threat List에서 위협을 선택하면 Threat Properties에 설명, 대응책, 참조가 표시됩니다.
  3. 상태 지정Not Started: 아직 검토 전. Needs Investigation: 확인할 사항이 있음. Not Applicable: 여기서는 일어날 수 없음, Justification에 이유를 적습니다. Mitigated: 통제가 적용됨, 대응책 필드에 통제를 적습니다.
  4. 위험 평가위험 필드를 채웁니다. 위협 검토와 위험 평가 참조.

Threat List는 열 머리글로 정렬하고 필터링할 수 있습니다. 예를 들어 Priority나 Interaction(흐름)으로 정렬하세요. 다이어그램을 바꾸면 TMT는 여전히 적용되는 위협의 검토 내용은 유지하고 새 위협만 추가합니다.

다른 모델을 열기 전에 현재 모델을 닫으세요

TMT 2016은 한 모델의 위협 목록이 표시된 상태에서 다른 모델을 열면 비정상 종료될 수 있습니다. 먼저 File > Close Model을 사용하세요.
