버전 및 라이선스#

2.0#

  • 각 위협이 제자리에서 한 번만 나타납니다. 위협 계열 8개와 계열별 앵커를 도입했습니다(위협이 생성되는 방식 참조). 게이트웨이 예제는 위협 230개에서 138개로 줄었으며, 줄어든 것은 반복과 적용될 수 없는 위협입니다.
  • 속성 축소. OT 위협에 쓰이지 않던 Microsoft 핵심 속성 31개를 제거했습니다. 구성요소 속성은 25개에서 16개, 흐름은 21개에서 7개, 데이터 저장소는 12개에서 3개가 되었습니다. 흐름 설정 세 개를 Threats on this Flow 하나로 합쳤습니다. 기록용 속성에는 표시를 붙였습니다.
  • 속성 적용성. 스텐실이 적용될 수 없는 속성(소프트웨어의 디버그 포트, USB, 무선, 물리적 노출)과 스텐실이 암시하는 속성을 고정합니다. 하드웨어 질문에 Not applicable 값이 추가되었습니다.
  • 새 속성. Assessment Scope(In scope, Supplier evidence, Out of scope), Runs on a Host Shown in the Model, Show Data Store Threats for Source Store.
  • 네트워크가 아닌 매체. Hardwired signal과 Local operator input. 채널 위협은 생략되고 배선 위협이 적용됩니다.
  • 중복 제거. 구체적인 위협이 같은 공격을 다루면 일반 도청, 재전송, DoS 위협은 빠집니다.
  • 새 위협. OT-E23 격리 우회, OT-T30·PL-T11 배선 변조, 읽기 전용 저장소의 저장 데이터 위협(R로 끝나는 ID). 새 스텐실: Product Supplier and Development Environment, Software Supply and Build Pipeline.

1.x에서 업그레이드하기#

  1. 먼저 1.x 위협 목록이나 보고서를 내보내세요. 2.0에서 빠지는 반복 위협의 검토 결과는 옮겨지지 않습니다.
  2. 모델을 열고 File > Apply Template로 2.0 템플릿을 적용합니다. 새 속성은 기본값으로 시작하며, Threats on this Flow = Auto는 1.x 방식으로 동작합니다.
  3. 앵커를 설정합니다: 각 구성요소로 들어오는 흐름 하나에 Threats on this Flow = All, 나머지에 Without component threats. 위협이 생성되는 방식 참조.
  4. 제거된 Microsoft 속성의 값은 사라집니다. 그곳에 기록한 내용이 있으면 먼저 요소 메모로 옮기세요. Generate Threats = No는 Threats on this Flow = None이 됩니다.

위협 ID는 그대로입니다.
