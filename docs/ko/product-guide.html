제품·시스템 위협 모델#

OT Product and System 템플릿으로 IEC 62443-4-2 구성요소(PLC, 게이트웨이, HMI 소프트웨어)나 IEC 62443-3-3 시스템(제어 시스템 솔루션)을 모델링하는 절차입니다.

1 범위→2 그리기→3 속성→4 앵커→5 생성→6 검토→7 요구사항→8 보고와 유지

1. 범위와 가정#

범위에 포함되는 것(제품, 인터페이스, 개발·업데이트 절차), 의도된 사용 방식, 그리고 가정을 적습니다. 예: "SL-T 2 영역의 잠긴 캐비닛에 설치". 이 내용은 File > Threat Model Information에 기록합니다.

2. 다이어그램 그리기#

구성요소 모델 (IEC 62443-4-2)#

  • 제품을 Component or Device Boundary로 감쌉니다.
  • 경계 안에서 제품을 기능별로 나눕니다: 런타임, 웹 인터페이스, 업데이트 서비스, 키 저장소, 펌웨어 이미지.
  • 컨테이너, 커널·사용자 공간, 안전 파티션처럼 격리가 중요한 곳은 Process or Privilege Boundary로 기능을 나눕니다.
  • 경계 밖에는 제품과 통신하는 모든 대상을 둡니다: 엔지니어, 운전원, 폴링하는 PLC, 클라우드, USB 메모리.

시스템 모델 (IEC 62443-3-3)#

  • 영역마다 IEC 62443 Security Zone을 하나씩 그립니다. 필요하면 Safety Zone SIS, Industrial DMZ Level 3.5, Enterprise or IT Zone을 추가합니다. 각 영역에 Purdue 수준과 영역 SL-T를 설정합니다.
  • 실제로 존재하는 흐름으로만 영역을 연결합니다. 영역 사이 경로에는 IEC 62443 Conduit와 Internet or Untrusted Network Boundary 선을 씁니다.
  • 각 장치에 맞는 스텐실을 고릅니다. IEC 62443-4-2 구성요소 유형(EDR, HDR, NDR, SAR)은 스텐실이 고정합니다.

공통#

제품 쪽으로 Software Supply and Build Pipeline 흐름 하나와 함께 Product Supplier and Development Environment를 추가합니다. 빌드·코드 서명 위협이 정확히 한 번 나타납니다.

3. 속성에 답하기#

대상 답할 내용
각 구성요소 웹 인터페이스, 사용자 계정, 저장된 비밀정보, 현장 업데이트, 서드파티 코드, 디버그 포트, 물리적 노출, 무선, USB, 레거시 플랫폼
각 흐름 프로토콜 보안, 제어 명령, 안전 데이터, 비밀정보, 물리적 매체
각 데이터 저장소 민감 데이터, 제어에 중요한 데이터

없는 기능에는 No로 답해 적용될 수 없는 위협을 없애세요. 소프트웨어 스텐실은 하드웨어 질문을 이미 Not applicable로 고정합니다. 모든 질문과 각 질문이 좌우하는 위협은 속성에 있습니다.

4. 구성요소마다 앵커 흐름 하나#

기본 비밀번호, 서명되지 않은 펌웨어, 로깅 부재 같은 구성요소 자체의 위협은 들어오는 흐름마다가 아니라 한 번만 나타나야 합니다.

  • 각 구성요소로 들어오는 흐름 하나(보통 가장 노출된 흐름)에 Threats on this Flow = All을 설정합니다.
  • 나머지 들어오는 흐름에는 Without component threats를 설정합니다.

명령줄 도구가 이 설정을 자동으로 해 주며, check_model.py는 빠진 곳을 알려 줍니다. 모두 Auto로 두면 일부 위협이 반복되는 1.x 방식으로 동작합니다. 위협이 생성되는 방식 참조.

5. 위협 생성#

View > Analysis View로 전환합니다.

6. 검토와 평가#

모든 위협을 살펴봅니다. 적용되는지, 이미 무엇이 대응하는지 판단한 뒤 가능성과 영향을 평가합니다. Relevant from SL로 정렬하면 목표 SL이 요구하는 항목을 볼 수 있습니다. 위협 검토와 위험 평가 참조.

7. 요구사항과 대응책#

각 위협에는 이를 다루는 IEC 62443-4-2 구성요소 요구사항(CR, EDR, HDR, NDR, SAR)이나 3-3 시스템 요구사항(SR)이 적혀 있습니다. 이를 제품 요구사항, 시험 항목, 인증 증거로 활용하세요.

고정 ID

OT-S01, OT-T23R 같은 위협 ID는 버전이 바뀌어도 변하지 않으므로 요구사항, 시험 보고서, 위험 등록부에서 참조할 수 있습니다.

8. 보고와 유지#

전체 보고서를 만듭니다. .tm7 파일을 설계 문서와 함께 보관하세요. 인터페이스, 프로토콜, 업데이트 절차가 바뀌면 갱신하고, IEC 62443-4-1 실무 2(SR-2, 위협 모델)가 요구하는 대로 릴리스마다 검토합니다.
