Command-line tools#

The source folder holds Python 3 tools for building and checking models outside TMT. They are optional: everything else on this site works in TMT alone.

Tool What it does
build_model.py Builds a .tm7 from an architecture description in JSON, with automatic layout, anchor flows, a preview picture and the predicted threat list
check_model.py Checks a .tm7: components whose threats would repeat or be missing, read-only stores, parallel flows
predict.py Predicts the threats TMT will generate, flow by flow
render_dfd.py Draws a preview picture of a model's diagram
tb7_to_kb.py Embeds a template in a model, like File > Apply Template
release_check.py Automated checks of the templates and examples before a release

Requirements: Python 3. For PNG previews you also need Playwright with Chromium; give the preview a .svg name to skip it.

Build a model from an architecture description#

cd source
python build_model.py ../examples/specs/gas_pipeline.json \
  "../OT Plant and Site Risk Assessment Template (IEC 62443).tb7" \
  "../my-site.tm7" --preview my-site.png

The description lists zones, elements, flows and line boundaries:

{
  "name": "Gas Pipeline - Site Risk Assessment",
  "zones": [
    {"id": "cc", "label": "Pipeline Control Centre - Level 2 and 3", "stencil": "SE.TB.B.OT.Zone",
     "props": {"ZonePurdueLevel": "Level 2 - Supervisory", "ZoneSLT": "SL 2"}}
  ],
  "elements": [
    {"id": "scada", "label": "Pipeline SCADA Server", "stencil": "SE.P.OT.SCADA", "zone": "cc",
     "props": {"UserAccounts": "Yes", "PatchStatus": "Patches pending"}},
    {"id": "oem", "label": "Compressor OEM Remote Support", "stencil": "SE.EI.OT.Vendor", "side": "left"}
  ],
  "flows": [
    {"label": "Station telemetry over cellular", "from": "scada", "to": "rtr", "stencil": "SE.DF.OT.DNP3",
     "props": {"ProtocolSecurity": "None", "CarriesControl": "Yes", "Medium": "Cellular"}}
  ],
  "lines": [
    {"label": "Carrier network to remote sites", "stencil": "SE.TB.L.OT.Internet",
     "crosses": ["Station telemetry over cellular"]}
  ]
}
  • Stencil IDs are listed on the Stencils page. Property names are the internal names, such as ProtocolSecurity or PatchStatus, and values are the values shown in TMT. The builder rejects unknown ones.
  • Layout. Zones are placed left to right in the order listed, so list them in Purdue order. Elements without a zone go on the left, right or bottom. The builder arranges elements and bends flows so that no flow runs through an element, and keeps everything inside TMT's drawing area. Override with "pos": [x, y] on an element or "bend": [dx, dy] on a flow.
  • Anchors. The builder sets Threats on this Flow: All on the most exposed flow into each element and Without component threats on the rest. For read-only stores it sets Show Data Store Threats for Source Store. Values you set in the spec are kept.
  • Output. You get the .tm7 with the template embedded, the predicted threats per flow and the preview picture. Open the model in TMT, switch to Analysis View and save.

Check a model#

python check_model.py "../my-site.tm7"

Run it after editing a model by hand or after applying the 2.0 template to an older model. It reports:

  • components shown on more than one anchor flow, or on none
  • components with several flows left on Auto
  • stores with no flow in and no source-store setting
  • parallel flows that would repeat the channel threats

Predict the threats#

python predict.py "../OT Product and System Threat Template (IEC 62443).tb7" "../my-model.flows.json"

build_model.py writes the .flows.json file next to the model. The prediction matches what TMT generates. For both examples, TMT showed exactly the predicted counts.

With Claude#

The ot-tmt-threat-model Claude skill wraps build_model.py. Give Claude a network architecture or an asset list, and it draws the data flow diagram and produces the .tm7.
